# RLS Policies Audit - CyberShield

## Overview

This document provides a comprehensive audit of Row-Level Security (RLS) policies in the CyberShield project, including intentional policies that use `true` expressions.

## Intentional `true` Policies

These policies use `USING (true)` or similar expressions intentionally and are considered secure:

### 1. `subscription_plans` - `authenticated_users_can_view_plans`
- **Table**: `subscription_plans`
- **Policy**: `SELECT USING (true)`
- **Justification**: Subscription plans are public pricing information. All authenticated users should be able to view available plans to make informed subscription decisions.
- **Risk Level**: LOW - No sensitive data exposed

### 2. `agent_versions` - `agents_can_read_versions`
- **Table**: `agent_versions`
- **Policy**: `SELECT USING (true)`
- **Justification**: Agent version information (version numbers, platform compatibility, release notes) is required by all agents for auto-update functionality. This is public software metadata.
- **Risk Level**: LOW - No sensitive data in version metadata

### 3. `ai_insights` - `System can insert insights`
- **Table**: `ai_insights`
- **Policy**: `INSERT WITH CHECK (true)`
- **Justification**: AI insights are generated by Edge Functions using service role. The INSERT policy allows system-level insertions. SELECT/UPDATE policies enforce tenant isolation.
- **Risk Level**: LOW - INSERT only, tenant isolation on read

### 4. `ai_actions` - `System can insert actions`
- **Table**: `ai_actions`
- **Policy**: `INSERT WITH CHECK (true)`
- **Justification**: Similar to ai_insights, actions are created by backend systems. Tenant isolation enforced on SELECT/UPDATE operations.
- **Risk Level**: LOW - INSERT only, tenant isolation on read

### 5. `ai_learned_patterns` - `System can manage patterns`
- **Table**: `ai_learned_patterns`
- **Policy**: `ALL USING (true)`
- **Justification**: AI patterns are managed exclusively by backend ML processes. Tenant-specific SELECT policy exists for admin viewing.
- **Risk Level**: MEDIUM - Backend-only access pattern, monitored via audit logs

### 6. `notification_log` - `System can insert notification logs`
- **Table**: `notification_log`
- **Policy**: `INSERT WITH CHECK (true)`
- **Justification**: Notification logs are created by Edge Functions after sending alerts. INSERT is system-only, SELECT is tenant-isolated.
- **Risk Level**: LOW - INSERT only, audit trail purpose

### 7. `performance_metrics` - `System can insert metrics`
- **Table**: `performance_metrics`
- **Policy**: `INSERT WITH CHECK (true)`
- **Justification**: Performance metrics are collected by Edge Functions for monitoring. INSERT is system-only, SELECT is tenant-isolated.
- **Risk Level**: LOW - INSERT only, monitoring purpose

## SECURITY DEFINER Functions

Functions that bypass RLS for legitimate internal operations:

| Function | Purpose | Security Justification |
|----------|---------|----------------------|
| `current_user_tenant_id()` | Returns caller's tenant_id | Used in RLS policies, no data exposure |
| `has_role()` | Checks user role | Used in RLS policies, returns boolean only |
| `is_super_admin()` | Checks super admin status | Used in RLS policies, returns boolean only |
| `update_user_role_rpc()` | Role updates with validation | Explicit super_admin escalation prevention |
| `cleanup_old_data()` | Housekeeping | Deletes expired data only, no read |
| `apply_agent_isolation()` | Isolate agents from network | **ADR-VELLUM-001**: Tenant ownership verified before action |
| `apply_agent_throttle()` | Rate-limit agent polling | **ADR-VELLUM-001**: Tenant ownership verified before action |
| `remove_agent_isolation()` | Restore isolated agents | **ADR-VELLUM-001**: Tenant ownership verified before action |
| `remove_agent_throttle()` | Remove rate-limiting | **ADR-VELLUM-001**: Tenant ownership verified before action |
