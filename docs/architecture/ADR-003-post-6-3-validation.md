## Gaps found and closed in this pass

### Gap A — CI `no-new-globals` gate would falsely fail
The old filter `_.Line -notmatch '^\s*<#'` only skipped the **opening** of
`<#...#>` blocks, so any docstring line in `Container.ps1` or
`SendHeartbeatUseCase.ps1` that mentioned `$Global:*` in prose would trip
the gate.

**Fix:** both gates (`no-new-globals` for hex layers and the
`monotonic-decrease` for legacy modules) now use the PowerShell Parser
tokenizer to strip ALL comments (line + block) before counting refs.

### Gap B — committed baseline counted differently than the gate
The first `baseline-globals.json` was generated by a Python regex that
counts at most one `$Global:` per line and accidentally matched docstring
mentions. The tokenizer-based gate counts every `$Global:*` reference and
ignores comments. Mismatches:

| Module | Old baseline | Tokenizer truth |
|---|---:|---:|
| crypto.ps1   | 10 | 12 |
| evidence.ps1 | 49 | 56 |
| network.ps1  | 27 | 31 |
| self-heal.ps1 | 10 | 11 |
| hmac.ps1     | 2  | 0  |
| notification.ps1 | 3 | 2 |
| update.ps1   | 10 | 9 |
| (others)     | unchanged | unchanged |
| **TOTAL**    | 144 | 154 |

CI would have flagged the first 4 rows as REGRESSIONS on the next push.

**Fix:** `baseline-globals.json` regenerated using the identical tokenizer
function the gate runs. Both numbers are now derived the same way, so any
divergence is a real code change. `counting_method` field added so future
contributors don't reintroduce the drift.

Validated locally: `gate.ps1` reports `GATE GREEN — all modules within
baseline`.
